# YUKTI Investment Analysis Prototype UI

> **Status: superseded, not retired.**
>
> The gap this README describes below — "until a future approved implementation
> connects institutional reasoning to those cases" — has been closed by
> [`workspace/`](../workspace/README.md), which is Version 1 of the YUKTI
> application and runs real analysis against user-created cases. The product
> vocabulary here (Case, Evidence, Positions, Conflicts, Decision Ledger) is
> what that application was built on.
>
> This prototype is kept for reference and is still fixture-backed. Retiring it
> touches a passing test suite and is scheduled work, not a side effect of
> building its replacement. Do not extend it.

This directory contains the product prototype for the YUKTI investment analysis
workflow.

The prototype is a static frontend built with plain HTML, CSS, and JavaScript.
The completed workspace experience still uses static fixture data. A separate
prototype panel can optionally call the local `prototype_risk_rik` development
server for the first executable Risk RIK vertical slice.

## Purpose

The goal is product iteration around an inspectable investment case workspace:

- creating an investment case
- inspecting a completed mock institutional judgment
- tracing decision ledger entries backward to contested propositions
- comparing independent RIK positions on the same proposition
- checking which evidence each position references
- distinguishing known facts, management claims, analyst inferences, and
  missing or unresolved information
- tracking unresolved questions and resulting investment conditions

## Mock Boundary

The canonical Northstar demonstration data comes from `fixtures.js`.
User-created cases are kept in browser memory for the current page session only
and do not inherit fixture evidence, RIK positions, propositions, Decision
Ledger entries, or institutional judgment.

The completed Northstar fixture is organized as:

```text
Evidence -> RIK Positions -> Conflicts -> Decision Ledger
```

For the Northstar fixture, the primary interaction starts from a Decision Ledger
entry and traces:

```text
Institutional Judgment -> Decision Proposition -> RIK Positions -> Evidence
```

This is a product mock. The fixture data does not represent actual DAALE system
output and must not be treated as a production contract.

## Prototype Risk RIK Boundary

The "Run Prototype Risk RIK" panel is separate from the fixture institutional
analysis. It posts case material to the local development endpoint served by
`applications.investment.prototype_risk_rik.server`.

This endpoint is not a production API, persistence contract, orchestration
layer, or canonical DAALE architecture. It exists only to connect prototype case
material to the existing prototype-only Risk RIK backend.

Required environment variables for real execution are documented in
`applications/investment/prototype_risk_rik/README.md`.

For deterministic development execution, set:

```powershell
$env:YUKTI_PROTOTYPE_RISK_RIK_PROVIDER = "deterministic"
```

The UI labels this mode as deterministic development execution. It must not be
read as live model reasoning.

Execution results render under "Prototype Execution Result" and are not merged
into the static institutional reasoning graph.

## Fixture Boundary

The Northstar institutional analysis is predefined demonstration data. It is
shown under "Fixture Institutional Analysis" and was not generated by the
current executable Risk RIK path.

User-created cases do not inherit Northstar evidence, propositions, RIK
positions, Decision Ledger entries, or institutional judgment. Until a future
approved implementation connects institutional reasoning to those cases, the UI
shows "Institutional Analysis Not Generated".

## Run

Open `index.html` directly in a browser.

No build step, package install, local server, or backend process is required.

To use the executable Risk RIK panel, run the local prototype bridge instead:

```powershell
$env:YUKTI_PROTOTYPE_RISK_RIK_PROVIDER = "deterministic"
python -m applications.investment.prototype_risk_rik.server
```

Then open:

```text
http://127.0.0.1:8765/
```
