# YUKTI Website — Editorial Voice Guide

Source: `YUKTI_Website_Mock_Copywriting_v1.docx` (supplied 2026-07-29). Reproduced
here so it lives next to the code it governs, per this project's practice of
keeping specs and implementation together.

Any copy — mock or final — must satisfy these rules before it goes into
[`homepage.content.js`](src/content/homepage.content.js):

- Write declaratively. Avoid hype, superlatives, and urgency.
- Prefer concrete nouns over adjectives.
- Never claim intelligence; demonstrate traceability.
- Never promise certainty; explain reasoning.
- Short paragraphs. Quiet confidence. Engineering before marketing.

This is the copy-equivalent of the Motion System's "no bounce, no overshoot"
rule (Motion System Rule 1) — a stylistic constraint that is actually a trust
mechanism, not a preference.
