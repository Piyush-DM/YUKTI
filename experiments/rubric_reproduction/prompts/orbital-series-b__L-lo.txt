# The investment reasoning rubric — literal transcription of the frozen pipeline

This document transcribes the behaviour of the frozen `choir_prototype` investment
pipeline into rules a reader (human or model) can execute by hand. It is the
rubric handed to the **L-lo control** in the `rubric_reproduction` experiment.

**It is a transcription, not a summary.** Every threshold, branch order, string
template, and default is copied from the source. Where the source does something
odd (for example: it computes a `uncertainty` field it never reads), this
document says so rather than tidying it.

## Section A — Translation: packet → CHOIR IR

No reasoning happens here. The translator maps shapes and preserves what the
packet said, including errors.

**Entities.** Exactly two, always:
`ent-company` (kind `company`, label = packet `company_name`) and `ent-market`
(kind `market`, label = `"<sector> market"`).

**Evidence.** One evidence item per source, in packet order:
`id` = the source `label` verbatim; `quality` = `_KIND_TO_QUALITY[kind]`, or
`ASSERTED` if the `kind` is not one of the five keys:

| source `kind` | evidence quality |
|---|---|
| `audit` | `AUDITED` |
| `management` | `REPORTED` |
| `interview` | `REPORTED` |
| `third_party` | `ESTIMATED` |
| `assertion` | `ASSERTED` |
| anything else | `ASSERTED` (default) |

**Claims.** One claim per `data_points` entry, in packet order:
`id` = `clm-NNN` where `NNN` is the 1-based index zero-padded to 3 digits
(`clm-001`, `clm-002`, …); `predicate` = the entry's `metric`; `value` = the
entry's `value` (a string); `evidence_ids` = the entry's `source_labels`
(verbatim, in order); `subject_id` = `ent-market` if the metric is one of
`tam_usd`, `market_growth_pct`, `competitor_count`, otherwise `ent-company`.

`uncertainty` = `_STATUS_TO_UNCERTAINTY[status]`, or `UNKNOWN` if `status` is not
one of the five keys:

| packet `status` | claim uncertainty |
|---|---|
| `confirmed` | `SETTLED` |
| `reported` | `LIKELY` |
| `estimated` | `LIKELY` |
| `disputed` | `DISPUTED` |
| `unknown` | `UNKNOWN` |
| anything else | `UNKNOWN` (default) |

**IMPORTANT — `uncertainty` is computed and then never read.** No kernel and no
synthesis step consults a claim's `uncertainty`. A `status` of `disputed` on its
own has **no effect** on any output. The only thing that creates a contradiction
is a `noted_conflicts` entry (below).

**Assumptions.** One per `stated_assumptions` entry, in order:
`id` = `asm-NNN` (1-based, 3-digit), `statement` = the text, `basis` =
`"stated in packet"`.

**Relationships.**
- One `SUPPORTS` relationship for every (claim, evidence_id) pair, i.e. for each
  claim, one per id in its `evidence_ids`. `source_id` = the evidence id,
  `target_id` = the claim id.
- One `CONTRADICTS` relationship per `noted_conflicts` entry **whose `metric`
  matches some claim's predicate**. `source_id` = `"packet-review"`,
  `target_id` = that claim's id, `note` = the conflict's `note`. A
  `noted_conflicts` entry whose metric matches no claim is silently dropped.

A "contradicted claim" is any claim that is the `target_id` of a `CONTRADICTS`
relationship.

**Dangling evidence is preserved.** If a data point lists a `source_label` that
no source defines, the claim still carries that id in `evidence_ids`. (Neither
sample packet does this, but a faithful transcription must state it.)

## Section B — Evidence quality ordering

`EvidenceQuality` ranks, strongest to weakest (`_EVIDENCE_RANK`):

| quality | rank |
|---|---|
| `AUDITED` | 3 |
| `REPORTED` | 2 |
| `ESTIMATED` | 1 |
| `ASSERTED` | 0 |

"Weakest evidence item" in a set = the item with the lowest rank; ties are broken
by ascending `id` (`_weakest` sorts by `(quality.rank, id)` and takes the first).

## Section C — The four kernels

The kernels run in this fixed order (`all_kernels()`):
**`financial_posture`, `risk_exposure`, `market_position`, `governance`.**

Each kernel is given the whole IR and returns one artifact:
`{kernel_name, findings[], evidence_references[], confidence, assumptions[],
unresolved_questions[]}`.

### C.0 — What every kernel does first (`_collect`)

For its `PREDICATES` list (given per kernel below), the kernel builds:

- **`found`**: for each predicate that appears as *some* claim's `predicate`, the
  **first** such claim (packet order). Predicates with no matching claim are
  simply absent from `found`.
- **`evidence`**: the de-duplicated union of the evidence items backing the
  claims in `found` — each claim's `evidence_ids` resolved to evidence items,
  **skipping any id that is not a real evidence item**, then sorted by `id`.
- **`contradictions`**: the count of claims in `found` whose id is a contradicted
  claim (Section A).

`found_inputs` passed to confidence derivation = `len(found)`.
`expected_inputs` = the length of the kernel's `PREDICATES` list.

`_number(claim)` = `float(claim.value)` if that parses, else `None`. (So
`audit_status = "audited"` reads as `None` numerically; the governance kernel
handles it as text.)

A finding's `evidence_ids` are taken from the **raw `claim.evidence_ids`** of the
claims it used (not the de-duplicated `evidence` set), except where a rule below
says otherwise (the runway / burn / multi-signal findings union and sort them).

### C.1 — `financial_posture`

`PREDICATES = ("arr_usd", "yoy_growth_pct", "gross_margin_pct",
"net_burn_monthly_usd", "cash_usd")` — `expected_inputs = 5`.

**Growth** — read `yoy_growth_pct` as a number `growth`.
- absent → add unresolved question: `"Year-over-year growth was not stated in the packet."`
- `growth >= 40.0` → stance `supports`, phrase `"Growth of {growth:.0f}% is strong"`
- else `growth >= 15.0` → stance `neutral`, phrase `"Growth of {growth:.0f}% is moderate"`
- else → stance `opposes`, phrase `"Growth of {growth:.0f}% is weak"`
- finding: `id "fin-growth"`, `topic "growth"`,
  `statement = "{phrase} against a 40% strong / 15% weak threshold."`,
  `claim_ids = (that claim's id,)`, `evidence_ids = that claim's evidence_ids`.

**Margin** — read `gross_margin_pct` as `margin`.
- absent → unresolved: `"Gross margin was not stated in the packet."`
- `margin >= 70.0` → `supports`, text `"Gross margin of {margin:.0f}% is healthy for the category"`
- else `margin >= 50.0` → `conditional`, text `"Gross margin of {margin:.0f}% is serviceable but thin"`
- else → `opposes`, text `"Gross margin of {margin:.0f}% is below the viable band"`
- finding: `id "fin-margin"`, `topic "revenue_quality"`, `statement = "{text}."`,
  `claim_ids = (claim id,)`, `evidence_ids = claim evidence_ids`.

**Runway** — read `cash_usd` as `cash`, `net_burn_monthly_usd` as `burn`.
- `cash` absent or `burn` absent → unresolved:
  `"Runway could not be derived: cash or net burn was missing."`
- else if `burn <= 0` → finding `id "fin-runway"`, `topic "capital_efficiency"`,
  stance `supports`, `statement = "Company is not burning cash; runway is unbounded."`,
  `claim_ids = (cash claim id, burn claim id)`, `evidence_ids = ()`.
- else:
  - add assumption: `"Runway is derived as cash / net monthly burn, holding burn flat."`
  - `runway = cash / burn`
  - `runway >= 18.0` → `supports`; else `runway >= 12.0` → `conditional`; else `opposes`
  - finding `id "fin-runway"`, `topic "capital_efficiency"`,
    `statement = "Derived runway is {runway:.1f} months against a 18-month comfort floor."`,
    `claim_ids = (cash claim id, burn claim id)`,
    `evidence_ids = sorted(set(cash claim evidence_ids) | set(burn claim evidence_ids))`.

**Confidence:** `derive_confidence(evidence, expected_inputs=5,
found_inputs=len(found), contradiction_count=contradictions)` (Section D).

### C.2 — `risk_exposure`

`PREDICATES = ("top_customer_revenue_pct", "net_revenue_retention_pct",
"logo_churn_pct", "net_burn_monthly_usd", "arr_usd")` — `expected_inputs = 5`.

**Concentration** — read `top_customer_revenue_pct` as `concentration`.
- absent → unresolved: `"Customer concentration was not disclosed."`
- `concentration >= 40.0` → `opposes`, text `"Top customer is {concentration:.0f}% of revenue -- severe"`
- else `>= 25.0` → `conditional`, text `"Top customer is {concentration:.0f}% of revenue -- elevated"`
- else → `supports`, text `"Top customer is {concentration:.0f}% of revenue -- diversified"`
- finding `id "risk-concentration"`, `topic "concentration_risk"`,
  `statement = "{text} against a 40% severe / 25% elevated threshold."`,
  `claim_ids = (claim id,)`, `evidence_ids = claim evidence_ids`.

**Retention / churn** — read `net_revenue_retention_pct` as `retention`,
`logo_churn_pct` as `churn`. Build a `signals` list and a `negative` flag.
- both absent → unresolved: `"Neither retention nor churn was disclosed."`
- otherwise:
  - if `retention` present:
    - `retention >= 110.0` → signal `"net revenue retention {retention:.0f}% is healthy"`
    - else `retention >= 95.0` → signal `"net revenue retention {retention:.0f}% is flat"`, set `negative`
    - else → signal `"net revenue retention {retention:.0f}% is eroding"`, set `negative`
  - if `churn` present:
    - `churn >= 15.0` → signal `"logo churn {churn:.0f}% is high"`, set `negative`
    - else → signal `"logo churn {churn:.0f}% is contained"`
  - finding `id "risk-retention"`, `topic "revenue_quality"`,
    stance `opposes` if `negative` else `supports`,
    `statement = "Revenue durability: {'; '.join(signals)}."`,
    `claim_ids = (retention claim id if used, then churn claim id if used)`,
    `evidence_ids = sorted(union of the used claims' evidence_ids)`.

**Burn efficiency** — read `net_burn_monthly_usd` as `burn`, `arr_usd` as `arr`.
- `burn` absent, or `arr` absent, or `arr <= 0` → unresolved:
  `"Burn efficiency could not be assessed: burn or ARR was missing."`
- else `ratio = (burn * 12) / arr`:
  - `ratio < 0.5` → `supports`; else `ratio < 1.0` → `conditional`; else `opposes`
  - finding `id "risk-burn"`, `topic "capital_efficiency"`,
    `statement = "Annualised burn is {ratio:.2f}x ARR against a 0.50x efficient / 1.00x unsustainable threshold."`,
    `claim_ids = (burn claim id, arr claim id)`,
    `evidence_ids = sorted(set(burn claim evidence_ids) | set(arr claim evidence_ids))`.

**Provisional flag.** After the findings above, for every claim in `found` (in
ascending id order) whose id is a contradicted claim, add unresolved question:
`"Claim {claim.id} ({claim.predicate}) is contradicted elsewhere in the packet;
this finding is provisional."`

**Confidence:** `derive_confidence(evidence, expected_inputs=5,
found_inputs=len(found), contradiction_count=contradictions)`. `assumptions = ()`.

### C.3 — `market_position`

`PREDICATES = ("tam_usd", "market_growth_pct", "competitor_count")` —
`expected_inputs = 3`.

**Opportunity** — read `tam_usd` as `tam`, `market_growth_pct` as `market_growth`.
Build `signals` and a `positive` flag.
- both absent → unresolved: `"No market sizing or market growth figure was supplied."`
- otherwise:

  - if `market_growth` present:
    - `market_growth >= 15.0` → signal `"market growing {market_growth:.0f}% a year"`, set `positive`
    - else → signal `"market growing only {market_growth:.0f}% a year"`
  - finding `id "mkt-opportunity"`, `topic "market_opportunity"`,

    `statement = "Market opportunity: {'; '.join(signals)}."`,

  - finding `id "mkt-competition"`, `topic "competitive_position"`,

**Assumptions.** For each item in the de-duplicated `evidence` set whose quality

## Section D — Confidence derivation (`derive_confidence`)

Inputs: `evidence` (the kernel's de-duplicated evidence set), `expected_inputs`,
`found_inputs`, `contradiction_count`.

Let `coverage_ratio = found_inputs / expected_inputs`
(`0.0` if `expected_inputs == 0`).
`coverage` string = `"{found_inputs}/{expected_inputs} expected inputs present"`.

The `derivation` list always starts with:
`"rule 0: inputs -- {n} evidence item(s), coverage {found_inputs}/{expected_inputs}
({coverage_ratio:.0%}), {contradiction_count} contradiction(s)"`
where `n = len(evidence)`.

Then, in order:

1. **No evidence.** If `evidence` is empty:
   add `"rule 1: no evidence at all -> INSUFFICIENT (stop)"`; return band
   `insufficient`, `limiting_factor = "no supporting evidence in packet"`,
   `evidence_floor = "none"`.
2. Otherwise add `"rule 1: evidence present -> continue"`.
3. **Coverage floor.** If `coverage_ratio < 0.5`:
   add `"rule 2: coverage {coverage_ratio:.0%} < 50% minimum -> INSUFFICIENT (stop)"`;
   return band `insufficient`, `limiting_factor = "incomplete input coverage"`,
   `evidence_floor = <weakest evidence item's quality value>`.
4. Otherwise add
   `"rule 2: coverage {coverage_ratio:.0%} >= 50% minimum -> continue"`.
5. **Start band from the weakest evidence item** (Section B). Rank → band:
   `3 → high`, `2 → moderate`, `1 → low`, `0 → low`.
   `limiting_factor = "weakest evidence is {weakest.quality.value} ({weakest.id})"`.
   Add `"rule 3: weakest evidence is {weakest.id} ({weakest.quality.value}) ->
   start at {band}"`.
6. **Contradiction downgrade.** If `contradiction_count > 0`:
   move the band **down one step per contradiction**, not past `low`
   (order `high → moderate → low`; `insufficient` is never reached this way).
   `limiting_factor = "{contradiction_count} contradicted claim(s) in scope"`.
   Add `"rule 4: {contradiction_count} contradiction(s) -> downgrade {before} to
   {after} (floor: low)"`.
   Else add `"rule 4: no contradictions -> no downgrade"`.
7. **Partial-coverage cap.** If `coverage_ratio < 1.0` **and** the band is `high`:
   set band `moderate`, `limiting_factor = "partial input coverage"`, add
   `"rule 5: partial coverage caps high -> moderate"`. Else add
   `"rule 5: no coverage cap applied"`.
8. Add `"result: {band} (limited by: {limiting_factor})"`.

`evidence_floor` in the non-early-return case = the weakest evidence item's
`quality.value`. `contradictions` on the confidence object = `contradiction_count`.

## Section E — Synthesis (`synthesize`)

Input: the four artifacts, in kernel dispatch order.

### E.1 — Topic views

Group every finding across all artifacts by its `topic`. Within a topic,
positions are kept in **artifact (kernel dispatch) order**. Topics are then
sorted alphabetically. A position records `{kernel_name, stance, statement,
finding_id}`.

- **Agreement** on a topic: it has **≥ 2 positions**, and the set of *non-neutral*
  stances among them has size exactly 1 (every kernel that took a side took the
  same side; `conditional` counts as a side here).
- **Disagreement** on a topic: the stance set (including neutral) contains **both
  `supports` and `opposes`**. (`conditional` vs `supports` is not a disagreement.)

### E.2 — Usable kernels

`usable_kernels` = the names of artifacts whose confidence band is **not**
`insufficient`, in kernel dispatch order.

### E.3 — Weighted tally (`_tally`)

Band weight: `high = 3`, `moderate = 2`, `low = 1`, `insufficient = 0`.

Walk the artifacts in order; for each, let `w` be its band weight; for each
finding:
- `supports` → `support_weight += w`
- `opposes` → `oppose_weight += w`
- `conditional` → `conditional_count += 1` (weight is not added)
- `neutral` → nothing

An `insufficient` kernel contributes weight 0, so its findings cannot move the
tally.

### E.4 — Decision rules (`_decide`), first match wins

Let `margin = abs(support_weight - oppose_weight)`,
`usable_count = len(usable_kernels)`, `total = 4`,
`disagreement_count = number of disagreement topics`.

Rules are evaluated in this order; the **first that fires** decides, and later
rules are not evaluated:

| Rule | Fires when | Outcome |
|---|---|---|
| **R1 insufficient-basis** | `usable_count < 2` | `insufficient basis` |
| **R2 live-disagreement** | `disagreement_count > 0` **and** `margin < 3` | `contested` |
| **R3 proceed-with-conditions** | `support_weight > oppose_weight` **and** `conditional_count > 0` | `proceed with conditions` |
| **R4 proceed** | `support_weight > oppose_weight` | `proceed` |
| **R5 decline** | `oppose_weight > support_weight` | `decline` |
| **R6 balanced-fallback** | otherwise (`support_weight == oppose_weight`) | `contested` |

Every rule that is evaluated is recorded as
`{name, condition, observed, fired, outcome}` — including the ones that fall
through — so the output's `rules_evaluated` lists R1 onward up to and including
the rule that fired.

`rationale` lines (not scored by the comparison, listed here for completeness):
- If R1 fires:
  `"Only {usable_count} of {total} kernels reached a usable confidence band; 2 are required."`
  and
  `"The packet has not been assessed. This is a statement about the evidence supplied, not about the opportunity."`
- If R1 does not fire, two lines are always added next:
  `"{usable_count} of {total} kernels reached a usable confidence band."`
  and
  `"Weighted support {support_weight} against opposition {oppose_weight}, with {conditional_count} conditional finding(s)."`
- If R2 fires:
  `"{disagreement_count} topic(s) carry directly opposing kernel findings and neither side leads by the 3-point margin required to treat the disagreement as settled."`
  and `"Both positions are reported. The disagreement is live, not resolved."`
- If there is a disagreement but R2 did not fire:
  `"{disagreement_count} topic(s) carry opposing findings, but the leading side is ahead by {margin}, clearing the 3-point margin."`
- If R3 fires: `"Support leads, but conditional findings remain outstanding; those become the conditions."`
- If R4 fires: `"Support leads with no conditional findings outstanding."`
- If R5 fires: `"Opposition leads on weighted findings."`
- If R6 fires: `"Support and opposition are exactly balanced."`

### E.5 — Institutional confidence (`_synthesis_confidence`)

- If `usable_count < 2` → band `insufficient`,
  `confidence_limiting_factor = "too few kernels reached a usable band"`.
- Otherwise, among the usable artifacts:
  - band = the **weakest** confidence band present (minimum, not mean; order
    `high` > `moderate` > `low`).
  - the "weakest contributing kernel" = the usable artifact with the lowest band
    weight, ties broken by ascending `kernel_name`.
  - `confidence_limiting_factor = "weakest contributing kernel is {name}
    ({that kernel's confidence limiting_factor})"`.
  - if `disagreement_count > 0`, prefix it:
    `"{disagreement_count} unresolved topic disagreement(s); " + <the above>`.

### E.6 — Remaining uncertainty (`_remaining_uncertainty`)

For each artifact in dispatch order: for each unresolved question `q`, emit
`"[{kernel_name}] {q}"`; for each assumption `a`, emit
`"[{kernel_name}] Assumed: {a}"`. Then sort the whole list of strings ascending.

## Section F — Citation rule (X4, `validate_artifact`)

Every id a finding cites in `claim_ids` or `evidence_ids`, and every id in an
artifact's `evidence_references`, **must be an id that exists in the IR** — i.e.
one of: the two entity ids (`ent-company`, `ent-market`), a claim id
(`clm-NNN`), an evidence id (a source label), an assumption id (`asm-NNN`), or a
relationship id (`rel-NNN`). A finding citing anything else is a hard failure.

Additional validation the runtime enforces:
- an artifact must have a non-empty `kernel_name`;
- an artifact must have at least one finding **or** at least one unresolved
  question (saying "I could not tell" is valid; saying nothing is not);
- the confidence object must carry a non-empty `limiting_factor` (evidence that
  it was derived, not authored).

`evidence_references` for each kernel = the ids of its de-duplicated `evidence`
set (Section C.0), in `id` order.

## Section G — What the output must contain

One JSON object: `{"artifacts": [<four artifacts, in dispatch order>],
"synthesis": {...}}`. Artifact and synthesis shapes are given in
`prompts/OUTPUT_SCHEMA.json`. The scored fields are: the recommendation, the
institutional confidence band, which decision rule fired, each kernel's band /
